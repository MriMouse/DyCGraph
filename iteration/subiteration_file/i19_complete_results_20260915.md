## 工作放大与候选裁决

CPU replay 是生产两阶段 mutation/reverse 接口的结构实验，只物化 union touched sources，reverse base 同样限制；没有 SSSP、真实 GPU publication/cache，oracle 和初始化排除于 service，RSS 包含 oracle。CPU replay 与完整系统时间不能相减求 GPU 时间。

WK p10/p90 实际邻接读/U 为 115.09/14.29，写入 bytes/U 为 225.21/34.44；FS 为 135.80/16.50、268.54/38.80。说明删除匹配及搬移存活边具有强工作放大；插入增加并不必然使维护更昂贵。规模增长时每 U 放大反而下降：TW100K→10M 写入 246.79→35.74 bytes/U，FS152.75→94.25 bytes/U，因为同 source 批量操作摊薄扫描/搬移。绝对维护成本仍大，不能写成每 U 放大随 B 单调上升。

所有比例十批末 overlay 为 1,000,000 条，规模两批末为 2B；本次候选契约使增删 pair 不跨池抵消，历史单调增长是已知边界。比例 CPU reverse merge 十批约 16–32 ms，远小于 0.48–0.81 s service，累计记录多不等于历史 merge 已主导。回收后 retired capacity 为 0；这不等于没有长期存活 overlay 或没有 arena 保留空间。所有 CPU 逐批增长、effective/reverse payload、RSS 详见下方完整表和原始 JSON。

**I20 选择：单次 source 规划的共享有效变更/紧凑 phase 表示。** 当前 forward effective 16 bytes/record，reverse 再复制同尺寸记录，大列表 radix 还有一份 scratch 与多次读写；编译布局表明 PreparedResult/PreparedSource/每 source apply metrics 分别约 200/168/216 bytes（还未计动态删除 run），多消费者重复表示是明确机会。优先删掉至少一种重型重复物化及遍历，而非只减少 malloc 次数。

预算：以本轮 TW/FS10M 为开发参照，grouping+forward prepare 两批约 3.999/4.664 s；到历史目标需净减少 1.362/3.378 s，相当于该部分 34.1%/72.4%。FS 难以只靠其中一小项追平，I20 不预许单独达标。预先规定同代码基线/候选固定 NUMA 交错配对，完整 P0 至少稳定改善约 5%作为继续投入的开发预算（TW/FS 各约 0.604/0.742 s）；同时每 U 准备字节/重复遍历下降。若只有局部 timer 好看、完整收益不稳、常规路径明显退化或语义/空间 gate 失败，则否决撤回。5% 是后续开发裁决预算，不是 I19 已证明的收益。

**I21 选择：限制 deletion 对存活邻接的改写范围，优先一个块级局部重建原型。** 暂不另起 reverse 历史整理路线，因为本轮历史 merge 证据弱。I20 完成后重算剩余预算：若仍需追平，目标净收益为 I20 后 P0 减历史目标；若可受影响的实测成本上界小于目标，不宣称该单候选足以追平。结构必须降低存活边写/U或实际访问/U，并计入 GPU 遍历/cache、整理/回收、host 空间与跨批债务；完整 P0 无改善或把成本转移到这些项则否决。不在本轮提前实现 PMA/tombstone/多套结构。

## 传输量与验收边界

本轮 correctness 开启已有显式 CUDA payload 账本，可分 initialization、update、check 查看；不能把含 checker 的总量与性能运行直接比较。仅当前系统有这些结果，**尚未完成原系统同口径传输量对比**。实际物理互连、完整 CPU memcpy、ZC/cache 分类访问未测；双方漏计 ZC 后只能比较显式 CUDA copy，不能命名总通信量。后续传输对比仍需独立准备，不能写成已排队或完成。

I19 主要 gate 达成：合法可复现的18组数据、比例及规模分开的结构/完整画像、正确性检查、主要时间来源与各一个后续机制/预算。观测仍有上述未测边界，effective 表示字节只覆盖已列出的 payload 与代码布局，不是全部内存流量。性能矩阵不扩展为额外图/比例；本轮没有执行 I20/I21/I22，也没有刷新原系统基线。
