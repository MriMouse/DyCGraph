本次根据用户“按照最新计划进行迭代”开始实施，覆盖原优化计划中“本次只修订、不执行”的历史限制。追平目标仍为 TW scaling 1000K/10000K、FS scaling 10000K 和 EU1000K；不恢复正式实验矩阵、参数扫描或已达标配置的专项优化。

## B7：显式拷贝 payload 计量接口

`CG_COMM_METER=1` 开启；默认关闭。`hybrid_sssp` 通过链接器 `--wrap=cudaMemcpy` / `--wrap=cudaMemcpyAsync` 统一捕获当前源码使用的显式 CUDA 拷贝。只对 API 成功返回的请求计数，记录调用的实际 size，不读取分配容量、不添加设备同步。异步请求是成功提交的 payload，不代表已完成，更不代表物理总线字节；运行失败时不能把已输出的部分计数当成完整结果。

`[I17-B7-COMM]` 按 batch/stage/category/direction 输出可相加的互斥记录。初始化、删除检查、批次检查、最终输出检查单列；addition、hotness、candidate、trace、eviction、compact、cache_load 独立归属。嵌套 category 采用最内层归属，不重复累计。日志在 paper timer 外输出，计数本身仍有诊断开销。

已标注 topology sparse publication、pull repair incoming、state gather、cache 和队列/位图 control；尚未细分类的请求保留 `other`。H2D/D2H/D2D/H2H 分列；`cudaMemcpyDefault` 保留 unclassified，不额外查询指针类型。

**边界与未完成项：** 本版本完成显式拷贝接口，不宣称 B7 全部完成。CPU `memcpy`、GPU kernel 内部 D2D、zero-copy 逻辑访问及 cache 命中分类尚未统计；物理互连字节不可用。上述项目在 contract 行明确标记 unavailable，不能作为零值，也不能由冷边存量推算。动态库内部 CUDA 调用及未来新增 2D/3D/driver API 需另行接入，当前源码未使用这些拷贝入口。

原版可复用同一 wrapper 源文件和链接选项，并在对应 batch/stage 边界调用 `Stage`/`Flush`、加上同类 scope；此处仅预留接入方法，未修改或重跑原版，没有形成跨系统通信量比较。

验证：`communication_meter_test` / `communication_meter_disabled_test` 覆盖实际请求字节、失败返回排除、异步方向、嵌套 scope 恢复、关闭和 flush 清零；三批 GPU capture、Bellman 与 CPU oracle 通过。首轮日志：`logs/i17b7_b5_20260914/communication_smoke.log`。最终 control 分类版本分别以开/关运行，日志为 `communication_final_smoke.log` / `disabled_final_smoke.log`；六个阶段 distance checksum 完全一致，关闭无 meter 输出。小图三批及 TW10000K 两批的 incoming payload 均与既有 repair h2d_bytes 逐批匹配，检查 gather 单列。一次紧邻 GPU 退出的关闭版启动被 busy 检查拒绝，后续串行重试已通过。

## B5：稀疏 mutation 统计空间精简（否决并撤回）

现有 TW10000K 日志显示每阶段约 259–279 万 changed sources，preflight 约 0.89–1.03 s（包含 reverse prepare，不能重复相加）。代码给每个 source 分配 `ChunkStoreBatchMetrics`，共 25 个 8 字节字段，worker 实际只写 `mutation_written_bytes` 和 `relocation_copied_bytes`。

尝试改用 16 字节 `MutationWriteMetrics`，保留原有计数累加、source 调度、删除/插入可见性和异常处理。该临时数组从每 source 200 字节降到 16 字节，下降 92%；按日志的 2591421/2791981 sources，单阶段少约 455/490 MiB。这是精确的该数组空间变化，不是整进程 RSS 或整批加速声明。

`source_local_chunk_store_test`、`dynamic_reverse_index_test` 和通信计量两项测试通过。修改前二进制冻结为 `logs/i17b7_b5_20260914/before_b5`。通过 `scripts/run_i17_target_check.py` 复用已有 command.json 做单项开发对照；本次单次配对不替代原三次中位数结果。

## B5：稳定 radix mixed-source grouping（保留，局部开发改善）

这是 mixed-source `GroupedUpdateBatch` 的 source 排序，不是已完成的 reverse effective-delta radix。原 mixed 分组仍使用 `std::stable_sort`，本轮每批约 1.5–1.7 s。大列表改为 4 个 8-bit 稳定 radix pass，小列表保留比较排序，按 source 排序后仍保留同 source 的原始 destination 顺序以及 delete-before-add 边界，不改变两个 phase 的提交语义。临时空间仍为 O(batch updates)，不按图顶点数分配桶；未保留被否决的 16 字节统计候选。

新增 `grouped_update_batch_test`，用独立 map 顺序 oracle 检查空批、4095/4096/4097 边界、十万条更新、重复边、完整 32-bit source ID 和 phase-active indices，已通过。连同 chunk-store、reverse、meter 开关共 5 项测试通过。

TW10000K 两批 `check=false`：紧邻基线 19030.224 ms，radix 17603.116 ms，单次配对下降 **7.50%**。mixed grouping 两批合计从 3067.270 ms 降到 1724.086 ms（下降 43.79%），最终 distance checksum 均为 `791729548754523982`。记录：`tw10000_radix/run.log`。这是开发筛选结果，不是重复中位数，不覆盖其他三个落后配置，也不替换性能大表；相对原版历史中位数 10715.850 ms 仍未追平。

同 cohort `check=true + CG_COMM_METER=1` 的两批完整距离/Bellman 检查已通过：两次 delete-stage、两次 batch、一次 final 均 `relaxable_edges=0 && missing_tight_witnesses=0`，最终 checksum 与上述运行相同。记录：`tw10000_radix_correctness/`。stored-parent 诊断仍有非零值（删除阶段 13/7，批末 12/7），按照现有契约仅作诊断，本轮未修复或宣称 parent correctness 封板。

这份运行只验证正确性和通信接口，不作性能结果。算法阶段显式 payload 汇总 H2D 429029668 bytes、D2H 167005320 bytes，不含初始化/检查，不含未测的 ZC 和物理互连。通信汇总入口为 `scripts/analyze_i17_communication.py <run.log>`；它要求运行完整成功，初始化/检查与算法 payload 分列，不补造 unavailable 的数值。
