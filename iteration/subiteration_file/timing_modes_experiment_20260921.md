# 2026-09-21：公平计时与模式适用边界实验

## 已确认的计时口径

论文：[Efficient Graph Data Access for Out-of-Memory GPU Streaming Graph Processing](https://www.vldb.org/pvldb/vol18/p3854-wang.pdf)，第 7 节、Table 4、7.2 breakdown。Table 4 是 **10 个 batch 累计秒数**，初始固定点先求出，再顺序执行每批至收敛；不是单批毫秒，也不是包含读图和初始化的进程耗时。论文默认 cache=4GB，A5000 24GB、双 Xeon Silver 4316、PCIe 4.0。当前机器为 V100-SXM2 16GB，不能假设不同硬件时延一致。论文 breakdown 包括增量计算、CPU 图更新和 GPU 热子图替换，zero-copy 通信包含在计算中。

主指标固定为：

`T = sum_batch(删除及修复 + 插入及传播 + CPU拓扑/索引维护与发布 + 热度/候选计算 + 缓存失效/驱逐/整理/装载 + 完成同步与剩余实际开销)`。

排除读图、分配初始结构、初始 SSSP、首次缓存装载、更新文件预读、独立正确性检查和最终结果导出。发生在 batch 内的惰性分配、索引重建、排序、cache 维护不可因为类似初始化而扣掉。保留第一批，不能以“热身”名义删掉较慢批次。阶段计时可能有异步重叠，主指标使用有同步边界的外层 P0，不能把部分阶段另加一次。进程 wall 单列，仅说明准备成本。

代码审计：当前 `samples/hybrid_sssp/hybrid_sssp.cu` 的 `sw_paper_batch` 包围删除以及插入到 cache 发布，前后 GPU 同步，删除阶段检查在停表后执行。基线采用 `logs/performance_matrix_20260912/bin/original`，对应冻结源码的 `sw_batch_total` 已在前后添加 GPU 同步，包含整个缓存刷新。未采用更老、缺少统一同步边界的 baseline binary。本轮不更改两个系统算法，不缩短主计时区间。

## 本轮实验矩阵

脚本：`scripts/run_timing_modes_20260921.py`。
输出：`logs/timing_modes_20260921/`。`manifest.json` 保存实际任务顺序、输入身份、参数和二进制 SHA256；`results.json` 每跑完一项更新；`report.md` 列总时间；`mode_comparisons.json` 在成组且 checksum 相同后生成相对速度。完整逐批 P0、attribution 与算法日志保留在每项 `run.log` 中。

1. 前台小测：OK1K，original/current × cache2/cache4，共 4 次、每次完整 10 批。用于判断合理口径是否已接近论文以及 cache4 是否值得继续。
2. 后台模式矩阵：EU、USA、TW、FS × 10K/100K/1M × road开关 × regular/large维护 × 两次重复，第二次反转配置顺序，共 96 次。反向索引统一 64 分片，固定 workers20、NUMA0、cache2。road 对应 `CG_ORDERED_REPAIR`（当前也控制插入 ordered 调度）；large 对应 `CG_BATCH_MAINTENANCE`。不把反向分片数量混入维护策略的单因素比较。
3. 后台阈值测试：四图每批 1M 的输入，第一批调整为 999,998 次更新，第二批为 1,000,002 次，其余批不动，总更新序列和总条数不变；测试 regular/large/auto × road开关 × 两次重复，共 48 次。每侧移动一个插入和一个删除；这确实改变了两个中间快照，因此仅在同一重分批输入内部比较模式，不把它与原分批输入的差异全归因于阈值。`I20-MODE` 记录实际选择，auto 的阈值为原始请求总数 >=1,000,000。
4. 后台补齐论文时延筛查：OK/WK/TW/FS/UK × 1K/10K/100K × original/current × cache2/cache4，共 60 次（含前台 4 次），单次只筛查量级和内存可行性，不挑最小值当正式性能。

合计 **204 次 GPU 运行**，同卡串行。不会并发抢同一 GPU，也不另开 GPU 共享 CPU 带宽。使用现有 GPU0 文件锁，运行中检查外来 GPU 进程，超时 30 分钟终止该配置、保留失败并继续后续任务；外来 GPU 进程或文件身份变化则停止队列。OOM、失败、不完整批次不参与有效模式比较。

路网 1M 保留 10 批；TW/FS 的 1M 使用既有扩展 cohort（不同底图/源点，只有两批）。因此扩展 cohort 单独命名、不接成同底图曲线、不乘五对齐论文。各模式之间始终保持相同输入、源点和批次数。

分析优先看每批 total（包括第一批、第二批、后续批）、整段总时间、删除/插入/cache 分解，区分稳定收益、个别批反转以及两开关交互。两次反序重复属于筛查；若差异小于波动，结论为不确定，后续正式对外性能结论需要更多重复及独立正确性验证。当前没有把任何模式写成“始终更快”。

输入大文件使用路径解析后的 size/mtime 身份检查（不是内容 hash）；二进制使用 SHA256。冻结当前关键源码及原始 baseline 计时源码，保留现有工作区所有修改。此次只新增 runner 和实验报告。
