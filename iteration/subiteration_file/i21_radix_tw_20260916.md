# I21 A+B：TW 1M优先、条件性10M

## 决策变化

用户最新授权：继续FS或TW 1M/10M，任一达成优于原系统即可，可依据证据改进预想方法。A两图均约5%且每对都改善，但未满足每对>=5%；本轮不宣称A已过严格门槛，允许作为组合候选继续B。优先TW，因为历史10M距目标约0.573秒，小于FS约2.183秒。TW1M当前也已低于历史2.242秒目标线，但历史跨系统checksum语义缺口仍在，不直接宣称正式战胜原系统。

## 实现

显式`CG_PARALLEL_SOURCE_RADIX=1`：GroupedUpdateBatch可接收已有mutation固定worker池，四轮8-bit稳定radix按连续逻辑分区计数，bucket-major/partition-minor全局前缀，独占输出区间scatter；不依赖worker实际执行顺序。相同source内记录顺序、重复destination顺序及delete-before-add保持。group物化仍串行，先隔离radix收益，不将整个group时间按微实验比例折算。未设置开关、无worker池、worker<=1或记录<4096使用原路径。新增I21-RADIX逐批记录实际选择。

额外空间为每worker 256个size_t直方图；scratch与原串行radix同规模。不创建额外worker池，不增加GPU分配，不修改reverse和prepare-before-forward异常契约。A+B组合开关仅开发实验显式启用，默认不改。

## 验证

hybrid_sssp构建、4项CTest通过。grouped_update_batch_test对串行和7-worker并行分别与独立map/输入顺序参考比较，覆盖0/1/4095/4096/4097/100000条、32位source、重复destination和不均匀分区。三个phase视图/索引保持相同。已有changed-source实际mutation与merge边界测试继续通过。

三批非对称GPU Bellman/CPU PQ smoke通过；该fixture每批4条，实际parallel=0，因此仅是组合开关下小batch回退/集成检查，不能冒充GPU大batch并行排序正确性。并行算法正确性由CPU独立参考测试覆盖；1M/10M运行还要求每批parallel接线正确及最终checksum匹配已有参考，不替代完整大图oracle。

## 后台队列

入口`scripts/run_i21_radix_queue.py`，目录`logs/i21_radix_tw_20260916/`，PID见pid，状态见queue_status.json与各规模status.json。

1. TW1M off/on/on/off，每次两批，共4次。off为A/B均关，on为A/B均开；同冻结二进制、large、20 workers、64 reverse shards、GPU0/NUMA0、cache2、SEGMENT512、ordered关闭。完整P0和阶段/source-work/records/RSS/采样GPU峰值均保留。
2. 只有TW1M两对完整P0收益均>=5%，才执行TW10M相同4次配对，否则停止待审阅。不会自动恢复FS矩阵或100M。
3. 10M显存提醒已在会话给出：本机V100 16GB，TW同cohort/cache2曾成功运行；新候选不增加GPU分配，因此在用户本轮明确10M授权下沿用原资源预算，不要求无证据的强制换卡。队列要求显存总量>=16384MiB，启动时GPU空闲且运行中检测外部进程。若运行OOM即停止，不自行降低cache或改变资源比较条件。FS更紧的预算未被此选择验证。
4. 所有输入先核对SHA256，保存环境/命令/冻结二进制hash，批次和最终checksum不匹配则失败停止。summary只标记待审阅，不自动启用候选，也不把历史目标线当正式原系统同语义配对。

当前已启动，收益待结果。健康确认后按用户计划不持续轮询长实验。若10M低于历史目标，后续仍须核对同输入/同资源原系统与共同结果指纹才能写正式胜出；若只过局部timer不算达成。
