# TW 插入/删除比例数据集

`prepare_tw_ratios.py` 以 `data/paper_data/TW/ready.json` 为参考，使用相同原始
TW 二进制、随机种子、按边出现次数均匀无放回采样、全源顶点排序稠密映射和批内
确定性打乱规则。重复边与自环按出现次数保留。

默认输出 `data/paper_data/TW_100_0`、`TW_75_25`、`TW_25_75`、`TW_0_100`。
每个目录都包含 `input_{1k,10k,100k}.txt`、`update_{1k,10k,100k}.txt`、
`stream_size_{1k,10k,100k}.txt`、`picks.bin` 和 `ready.json`。

| 插入/删除百分比 | 1k 每批插入/删除 | 10k 每批插入/删除 | 100k 每批插入/删除 |
|---|---|---|---|
| 100/0 | 1000/0 | 10000/0 | 100000/0 |
| 75/25 | 750/250 | 7500/2500 | 75000/25000 |
| 25/75 | 250/750 | 2500/7500 | 25000/75000 |
| 0/100 | 0/1000 | 0/10000 | 0/100000 |

每个规模均为 10 批。初始图等于完整原图减去该规模选中的插入边；选中的删除边
在初始图中存在。三个规模分别使用插入池、删除池的嵌套前缀。四组比例共享原有
TW 种子生成的同一百万个边出现位置及其打乱顺序，按比例将前缀划为插入池、
其余划为删除池；因此不同比例的初始图不同。更新行是 `a/d src dst 1`，
`stream_size` 每行先插入数、后删除数。0% 的操作允许计数为零。

构造仅使用 CPU，不调用 GPU，但会进行大量源文件扫描、顶点映射、文本格式化和
磁盘写入。当前 TW 四组共需约 386.5 GiB 新空间，应在计时实验结束后运行。
默认顺序构造四组；不修改现有 `TW` 数据。`.part` 文件完成后才改名，最后写入
`ready.json`；失败后可使用 `--resume` 重建参数匹配的未完成目录，已完成目录会跳过。

先查看参数和空间估算：

```bash
python3 scripts/prepare_tw_ratios.py --dry-run
```

实验结束后，在仓库根目录后台启动：

```bash
mkdir -p logs
nohup nice -n 19 ionice -c 3 python3 -u scripts/prepare_tw_ratios.py > logs/prepare_tw_ratios.log 2>&1 &
```

低优先级仍可能影响实验，不建议和计时实验同时运行。每组的详细生成进度在
对应目录 `generation.log`，状态在 `status.json`。

可用 `--insert-percent 75 25` 只生成指定比例，或 `--output PATH` 指定新输出根目录。
合成数据回归验证：`python3 tests/tw_ratios_test.py`。

现有 `paper_data_stream.cpp` 仅增加可选的插入百分比参数；原有不带该参数的调用
仍使用 50/50，文件内容保持一致。
